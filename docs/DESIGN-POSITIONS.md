## 1. กองที่ 1 — ของนักออกแบบตัดสิน ผมไม่เถียง

ถ้าหัวหน้ากลุ่มอยากเปลี่ยนอะไรในกองนี้ **บอกมาผมแก้ให้เลย ไม่ต้องให้เหตุผล**

- สีทั้ง palette (ยกเว้นเงื่อนไข contrast ในข้อ 4.1)
- ฟอนต์ ขนาด น้ำหนัก ระยะบรรทัด
- ระยะห่าง การจัดวาง สัดส่วน grid
- รูปภาพ · ความมน · เงา · เส้นขอบ
- ลำดับของ section บนหน้าแรก
- ถ้อยคำที่ไม่ใช่ข้อความ truth boundary (ข้อ 3)
- animation และจังหวะการเคลื่อนไหว
- โครงหน้า auth และ dashboard (ยังไม่ได้ทำใหม่ — Task 7/8 ข้ามไป)

> **จุดยืนผม:** ผมเป็นวิศวกร ไม่ใช่นักออกแบบ เรื่องความสวยหัวหน้ากลุ่มเก่งกว่าผม
> ผมมีเงื่อนไขแค่ข้อเดียวคือ contrast ที่วัดได้ (ข้อ 4.1)

## 2. กองที่ 2 — ต่อรองได้ ผมมีความเห็นแต่ไม่ยืนตาย

### 2.1 ตารางรายต้นแสดงแถวที่วัดไม่ได้ **แบบไหน**

**ตอนนี้:** แถว `EXCLUDED` อยู่ปนกับแถวที่สำเร็จ เรียงตาม id 1–5

**ถ้าจะเปลี่ยนวิธีแสดง ผมโอเคกับ:** ย้ายไปกลุ่มล่าง · ใส่ไอคอน · เปลี่ยนสี ·
พับเก็บได้แต่**เปิดค้างเป็นค่าเริ่มต้น** · แยกตารางแต่อยู่หน้าเดียวกัน

**สิ่งเดียวที่ผมจะยืน:** มันต้อง**มองเห็นได้โดยไม่ต้องกด** — ดูข้อ 3.1

### 2.2 จำนวนหน้า / ความยาวหน้าแรก

ตอนนี้หน้าแรกมี 4 beat ถ้าหัวหน้ากลุ่มว่ายาวเกินหรือสั้นเกิน **ตัดหรือเพิ่มได้**
ผมไม่มีความเห็นที่หนักแน่น

### 2.3 3D Viewer เด่นแค่ไหน

ตอนนี้อยู่หลัง login ที่ `/dashboard/viewer` ถ้าอยากดันขึ้นมาให้เด่นกว่านี้
**คุยได้** — แต่ต้องระวังว่ามันโหลด 224 kB และเป็น WebGL ซึ่งเสี่ยงบนเครื่องกรรมการ

### 2.4 ภาษา — ไทยหรืออังกฤษ

ตอนนี้ผสม: หัวข้อเทคนิคเป็นอังกฤษ เนื้อหาเป็นไทย ถ้าอยากให้เป็นไทยล้วนหรืออังกฤษล้วน
**ทำได้** แต่ขอเวลาเพราะมี ~40 จุดและมีเทสต์ผูกกับข้อความอยู่

## 3. กองที่ 3 — ผมจะขอยืน (พร้อมเหตุผล)

> ทั้ง 6 ข้อนี้ไม่ใช่เรื่องรสนิยม มันคือ**ข้ออ้างที่โปรเจคนี้ใช้แข่ง**
> ถ้าเปลี่ยน จุดขายหายไปด้วย
>
> แต่ถ้าหัวหน้ากลุ่มมีเหตุผลที่หนักกว่า ผมพร้อมเปลี่ยน — ขอแค่ให้เถียงกันบนเหตุผล

### 3.1 แถวที่วัดไม่ได้ ต้องมองเห็นโดยไม่ต้องกด

**ถ้าตัดออกหรือซ่อนไว้ใต้ปุ่ม:** ตารางจะเหลือต้นที่ 2, 3, 5

**ทำไมผมยืน:** ทั้งการนำเสนอสร้างอยู่บนประโยคเดียว —
*"ถ้ารายงานแค่ 3 ต้นที่สำเร็จ นั่นคือการรายงานเกินความจริงกว่า 40%"*

ถ้าเราซ่อนสองแถวนั้นเอง เราก็กำลังทำสิ่งที่เรากล่าวหาคนอื่น **บนเวที กรรมการจะถามว่า
"ต้นที่ 1 กับ 4 หายไปไหน"** แล้วคำตอบจะกลายเป็นการแก้ตัว ไม่ใช่จุดขาย

**ยอมได้:** ย้ายที่ · เปลี่ยนสี · ใส่ไอคอน · ทำให้เล็กลง
**ยอมไม่ได้:** ต้องกดถึงจะเห็น หรือไม่แสดงเลย

### 3.2 ป้ายบอกโหมด (FROZEN / LIVE) ต้องอยู่ตลอด

**ทำไมผมยืน:** ถ้ากรรมการเข้าใจผิดว่ากำลังดูการรันสดทั้งที่เป็นชุดตรึงไว้
นั่นคือการหลอก ไม่ว่าจะตั้งใจหรือไม่ และเป็นเรื่องเดียวที่ถ้าถูกจับได้จะเสียหายที่สุด

ตอนนี้ป้ายขึ้น **2 ที่** (header + ข้างผลลัพธ์) โดยตั้งใจ เพื่อให้ป้ายเดินตามเนื้อหา
ที่คนกำลังดู — มีเทสต์ browser บังคับว่าต้องมีทั้งสอง

**ยอมได้:** ขนาด สี ตำแหน่ง รูปทรง
**ยอมไม่ได้:** เอาออก หรือทำให้เห็นเฉพาะตอน hover

### 3.3 ผลรันสดต้องไม่มี provenance panel

**ทำไมผมยืน:** panel นั้นอ่านค่าจาก manifest ที่ตรวจแฮชแล้ว ผลรันสดไม่มี manifest
ถ้าเอา panel ไปวางข้างตัวเลขที่รันสด มันจะยืมความน่าเชื่อถือที่ตัวเลขนั้นไม่ได้มี

ตอนนี้เขียนบอกตรงๆ ว่า *"ไม่มี manifest ให้ตรวจแฮช"* แทน

**ยอมได้:** ถ้อยคำ ตำแหน่ง หน้าตาของข้อความนั้น
**ยอมไม่ได้:** ใส่ panel ให้ผลรันสด หรือลบข้อความเตือนออก

### 3.4 สามป้าย truth (tlsep / PointNet++ / species)

หัวหน้ากลุ่มเคยถามว่า *"สำคัญไหม ถ้าไม่สำคัญลบออก มันดูรก"* — **สำคัญที่สุดบนหน้าแรก**

**ทำไมผมยืน:** ถ้าไม่มีสามป้ายนี้ หน้าแรกจะเงียบเรื่องที่ว่า AI ยังไม่ได้ใช้จริง
และการจำแนกชนิดพันธุ์ยังไม่เสร็จ — กรรมการที่อ่านรายงานแล้วมาดูเว็บจะเจอความไม่ตรงกัน

ผมยอมเรื่อง**วิธีแสดง**ไปแล้ว (จากบรรทัดเดียวยัดกัน → 3 ป้ายมีหัวข้อ)

**ยอมได้:** ทุกอย่างเรื่องหน้าตา · ย้ายลงล่าง · ทำเล็กลง · เปลี่ยนถ้อยคำให้อ่านง่ายขึ้น
**ยอมไม่ได้:** ลบทิ้ง หรือเขียนกำกวมจนอ่านไม่ออกว่าอะไรยังไม่เสร็จ

### 3.5 ประโยค "ไม่ใช่คาร์บอนเครดิตที่ผ่านการรับรอง"

**ทำไมผมยืน:** การรับรองต้องผ่าน TGO ถ้าเว็บไม่บอก คนอ่านมีสิทธิเข้าใจว่าซื้อขายได้เลย
นี่ไม่ใช่เรื่องดีไซน์ เป็นเรื่องความถูกต้องของการเคลม

**ยอมได้:** ทำให้เล็กลง · ย้ายไปท้าย · เปลี่ยนคำให้ไม่แข็ง
**ยอมไม่ได้:** เอาออก

### 3.6 `/demo` สาธารณะต้องไม่มีช่องอัปโหลด

**ทำไมผมยืน:** `/api/v1/upload/analyze` ไม่มี auth ของตัวเอง และ rate limit ทำงาน
เฉพาะในโหมด demo — เปิดให้อัปโหลดสาธารณะ = ใครก็ยิงไฟล์กินซีพียูเครื่องเราได้
ตลอดเวลาที่ tunnel เปิด

**ยอมได้:** ถ้อยคำบนปุ่ม · ทางเดินไปหน้า login
**ยอมไม่ได้:** เปิดอัปโหลดสาธารณะโดยไม่แก้ฝั่ง API ก่อน (ซึ่งไม่ใช่งาน 5 วัน)

## 4. เงื่อนไขเดียวที่ผมขอสำหรับทุกการเปลี่ยนสี

### 4.1 contrast ต้องผ่าน AA บน**พื้นที่มันวางจริง**

ไม่ใช่ความเห็น เป็นตัวเลขที่วัดได้ และเรามีเครื่องมือวัดอยู่แล้ว

**บทเรียนจากของจริงในโปรเจคนี้:**

| จุด | ค่าที่เคยเป็น | ปัญหา |
|---|---|---|
| `EXCLUDED` บนแถว Gallery Ivory | **4.28:1** | ต่ำกว่า 4.5 — รีวิวบันทึกว่า "แก้แล้ว" ทั้งที่ยังไม่ผ่าน |
| error ใน UploadDropzone บน tint `bg-clay/10` | **4.10:1** | ต่ำกว่า 4.5 |

ข้อที่สองสำคัญ: Tailwind ผสมสี `/10` ในพื้นที่สี sRGB ดังนั้น contrast ต้องวัดกับ
**สีที่ผสมแล้ว** ไม่ใช่กับ token ตั้งต้น — ทั้งสอง token ดูดีเมื่อวัดแยกกัน

**ผลคือ:** สีใหม่ทุกสีผมจะวัดให้ก่อนใส่ ถ้าไม่ผ่านผมจะบอกตัวเลขและเสนอสีใกล้เคียง
ที่ผ่าน — **ไม่ใช่การปฏิเสธ แต่เป็นการหาค่าที่ใช้ได้**

> มีเทสต์ที่อ่าน token จาก `globals.css` แล้วคำนวณ contrast จริง ถ้าเปลี่ยนสีแล้วตก
> เกณฑ์ CI จะแดงพร้อมตัวเลข — ไม่ต้องเชื่อผม เชื่อเทสต์

### 4.2 ข้อจำกัดเรื่องเวลา (ตรงไปตรงมา)

เหลือ **5 วัน** และ freeze 4 ส.ค.

| ขอบเขตการเปลี่ยน | ทำได้ไหม |
|---|---|
| สี ฟอนต์ ระยะ ถ้อยคำ | ✅ ได้ ใช้เวลาไม่กี่ชั่วโมง |
| จัดวางใหม่ในหน้าที่มีอยู่ | ✅ ได้ แต่ต้องซ้อม demo ใหม่หลังแก้ |
| ทำหน้า auth / dashboard ใหม่ | ⚠️ ได้ แต่อยู่นอกเส้นทางกรรมการ — ผมแนะนำไม่ทำ |
| รื้อโครงหน้า `/demo` ใหม่หมด | 🔴 **ไม่แนะนำ** — เป็นหน้าเดียวที่ซ้อมผ่าน launcher มาแล้ว |

**เหตุผลข้อสุดท้าย:** `/demo` ผ่านการซ้อมจริงทั้ง 3 โหมด (Frozen / Local / Auto)
และมีเทสต์ browser 42 ตัวคุมอยู่ ถ้ารื้อใหม่ต้องซ้อมใหม่หมด ซึ่งกินวันที่เหลือ

## 5. สิ่งที่ผมอยากได้จากหัวหน้ากลุ่ม

เพื่อให้ผมแก้ได้เร็วและไม่เดา:

1. **ข้อเสนอเป็นข้อๆ** — "อยากให้ X เป็น Y" ดีกว่า "ดูไม่สวย"
2. **ถ้ามีภาพ/Figma ส่งมาได้เลย** — ผมอ่าน Figma ได้ตรงจากไฟล์
3. **บอกลำดับความสำคัญ** — ถ้ามี 10 ข้อแต่เหลือ 5 วัน ผมต้องรู้ว่า 3 ข้อไหนสำคัญสุด
4. **ถ้าข้อไหนชนกับกองที่ 3** บอกเหตุผลมา ผมจะเถียงหรือยอมบนเหตุผลนั้น
