| สิ่งที่ขึ้นบนจอ | แปลว่า | ทำต่อยังไง |

| `Mode: LOCAL LIVE` | รันสดบนเครื่องนี้ | สาธิตเต็มรูปแบบ **พูดตรงๆ ว่ารันบนเครื่อง** |

### บรรทัด `Site:` บอกว่ากรรมการเปิดเองได้ไหม

Auto จะอัปเดตเว็บจริงให้ชี้มาที่ tunnel ของรอบนี้ แล้ว**ตรวจว่าเว็บรับค่าใหม่แล้วจริง**
ก่อนบอกว่าเสร็จ ขั้นนี้เป็น Vercel build จึงกินเวลา 2–4 นาที

| บรรทัดที่ขึ้น | แปลว่า |
|---|---|
| `Site: anyone can open treeqcarbon.vercel.app and use this demo.` | **กรรมการเปิดเองจากเครื่องไหนก็ได้** |
| `Site: use the browser tab this launcher opens.` | อัปเดตเว็บไม่สำเร็จ — ใช้ได้เฉพาะแท็บที่ launcher เปิด |

อันล่างไม่ใช่ของพัง tunnel ยังทำงาน สาธิตบนโน้ตบุ๊กเราได้ครบ แค่คนอื่นเปิดเองแล้ว
จะเจอ backend ของรอบก่อน

**ถ้ารีบและไม่ต้องให้ใครเปิดเอง** ใส่ `-SkipPublish` จะข้ามการ build ไปเลย เร็วขึ้น 2–4 นาที

## 2. 15 นาทีก่อนขึ้นเวที

1. ปิดโปรแกรมที่กินพอร์ต 3000 กับ 8000 ให้หมด (โดยเฉพาะ dev server ที่ลืมปิด)
2. เปิด `Desktop\CarbonScrip\TreeQ-Demo-Start.bat` — **ตัวบน Desktop เท่านั้น**
3. รอจนบรรทัด `Mode:` ขึ้น
4. **ทดสอบอัปโหลดหนึ่งครั้งด้วยไฟล์จาก USB** — อย่าให้ครั้งแรกที่กดคือตอนกรรมการดู
5. กด `เริ่มใหม่` ให้จอสะอาด แล้วปล่อยทิ้งไว้

เวลาที่ควรได้ (จับเวลาจากการซ้อมจริง 29 ก.ค. 69 บนเครื่องที่จะใช้แข่ง):

| โหมด | เวลาจนพร้อม | ที่วัดได้ |
|---|---|---|
| Frozen | ~7 วินาที | 7.0 |
| Local | ~7 วินาที | 6.5, 6.4 |
| Auto | **40–50 วินาที** | 48.2, 38.2 |

Auto ช้ากว่าเพราะ **ตั้งใจรอ 25 วินาที** ก่อนเช็ค hostname สาธารณะครั้งแรก — ถ้าเช็คเร็วกว่านั้น
DNS จะตอบ "ไม่มี host นี้" แล้ว **cache ไว้ 30 นาที** ทำให้โหมด public ใช้ไม่ได้ทั้งรอบ

> **อย่าปิดหน้าต่างเพราะคิดว่ามันค้าง** — ระหว่างรอจะมีบรรทัด
> `Public hostname published; holding 25s before the first lookup` ขึ้นให้เห็น
> ถ้าเห็นบรรทัดนี้แปลว่ากำลังทำงานปกติ

ถ้าคิดว่า 40–50 วินาทีนานเกินไปสำหรับจังหวะขึ้นเวที ให้เปิด launcher ทิ้งไว้ตั้งแต่ก่อนถึงคิว
หรือใช้ `-Mode Local` ซึ่งพร้อมใน 7 วินาทีและสาธิตได้ครบเหมือนกัน

## 4. เมื่อพัง — ทำอะไรตรงไหน

### จอขึ้น `Mode: FROZEN` ทั้งที่อยากได้ live

ไม่ต้องแก้ **สาธิต Frozen ไปเลย** แล้วพูดว่า
"ตอนนี้เน็ตในห้องไม่เสถียร ผมใช้ชุดหลักฐานที่ตรวจแฮชไว้แล้วแทน ตัวเลขชุดเดียวกัน ตรวจสอบย้อนได้"

การพยายามซ่อมสดหน้ากรรมการเสียคะแนนมากกว่าโหมด Frozen เยอะ

### `ERROR: Port 8000 is already in use`

มีของเก่าค้าง ปิดแล้วเปิดใหม่:

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

### อัปโหลดแล้วขึ้น "โทเคนของรอบสาธิตหมดอายุแล้ว"

โทเคนผูกกับ launcher หนึ่งรอบ แท็บที่เปิดค้างจากรอบก่อนจะถือโทเคนเก่าที่ API ไม่รู้จักแล้ว

**ปิดแท็บนั้น แล้วใช้ลิงก์ที่ launcher รอบปัจจุบันเปิดให้** — รีเฟรชเฉยๆ ไม่ช่วย เพราะหน้าเว็บ
เก็บโทเคนเก่าไว้ใน sessionStorage

### อัปโหลดแล้วขึ้น "เซิร์ฟเวอร์ปฏิเสธไฟล์นี้"

ไฟล์ไม่ใช่ `.ply` ที่ header ถูก — โหมดเดโมรับ **เฉพาะ `.ply`** ใช้ไฟล์จาก USB แทน

### อัปโหลดแล้วขึ้น "ติดต่อบริการวิเคราะห์ไม่ได้"

API ตายระหว่างรัน ปิด launcher เปิดใหม่ ถ้าเปิดใหม่แล้วยังไม่ได้ → ใช้ `-Mode Frozen`

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\demo\start-treeq-demo.ps1 -Mode Frozen
```

### เน็ตในห้องล่ม

`-Mode Local` ไม่ใช้เน็ตเลย ยังอัปโหลดและคำนวณได้ครบ

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\demo\start-treeq-demo.ps1 -Mode Local
```

### ต้องเปิด API เองด้วยมือ (นอก launcher)

ใช้ **venv ของ repo เท่านั้น** — Python ที่ติดตั้งในเครื่องไม่มี `uvicorn`

```powershell
cd D:\Project_Carbon\services\api
$env:CORS_ORIGINS='http://localhost:3000,https://treeqcarbon.vercel.app'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

**ห้ามตั้ง `TREEQ_DEMO_MODE`** ถ้าไม่ได้เปิดผ่าน launcher — API ที่เปิด demo mode ค้างไว้บนพอร์ต
8000 คือสาเหตุที่ทุกการอัปโหลดเคยตอบ 401 โดยไม่มีอะไรบนจอบอกว่าทำไม

### ทุกอย่างล่ม

เปิด `apps/web/public/demo/result.json` แล้วอธิบายจากตัวเลขตรงๆ ยังดีกว่าไม่มีอะไรให้ดู
